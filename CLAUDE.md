# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

`code-helper` — pip-installable Python CLI that generates and manages small bash wrapper scripts in `~/.local/bin`. Each wrapper points a **coding agent** (Claude Code, Codex) at a **model backend** (a local Ollama daemon, Z.ai, ...) under a name you choose. Not affiliated with Z.ai, Moon Bridge, or Codex — successor to the archived `zai-codex-helper` project, stripped down to just this one feature.

A wrapper is a point in **agent × provider × model**:

```bash
code-helper add glm-ollama                                  # a curated preset
code-helper add --agent codex --provider ollama \
                --model glm-5:cloud                         # -> ~/.local/bin/glm-5-codex
code-helper list matrix                                     # which pairings exist
```

## Commands

```bash
pip install -e ".[dev]"        # editable install + dev tools
pytest -q                       # run tests
ruff check . && ruff format .   # lint + format (the project's only linter)
```

## Architecture

Three-layer split, much smaller than the archived predecessor:

- **`cli/parser.py`** — argparse tree (`list [wrappers|agents|providers|matrix]` / `add [<preset>] [--agent A --provider P --model M] [--alias N] [--shape S] [--force] [--list-models]` / `edit-token [<name>]` / `tui`, plus bare `code-helper` defaulting to `tui`). `list matrix` is executable documentation: it renders by calling `resolve_shape` itself, so it cannot disagree with what `add` accepts. `_confirm_overwrite` is `isatty`-gated — off a TTY it refuses *without reading stdin*, which is what keeps a scripted run from hanging. Handlers are thin shells: resolve `Paths.default()`, delegate to a service, let `CodeHelperError` propagate to `__main__.main()`.
- **`cli/menu.py`** — a hand-rolled arrow-key terminal menu (`select_from_menu`), stdlib-only (`termios`/`tty`/`select`, Unix-only) — consistent with "No Rich/Typer" below. Split into two layers: `_translate(first_byte, read_more)` is a PURE key-sequence parser (no TTY) that turns a byte plus an injectable non-blocking `read_more(timeout) -> str | None` peek into a key name — fully unit-tested in `tests/test_keys.py` without a real terminal; `_read_key_raw` is the thin `termios`/`tty` wrapper that owns the real TTY (via `os.read(fd, 1)`, never `stream.read(1)` — see note below) and feeds `_translate`. `select_from_menu` takes `read_key` as an injectable callable so tests never touch a real TTY. Menu items are `str` or `(value, label)` pairs — the label renders, the value is what callers compare against and what gets returned; a plain `str` is both, so every pre-existing call keeps working. Items are numbered `1`-`9` in the printed gutter by the menu itself (not the caller) — the same place that handles the `DIGIT_<n>` key — so the shown number and the number that selects it can never drift apart; the cap is exported as `MAX_DIGIT_ITEMS` because a caller rendering its own key hint must not promise more digits than exist (a 21-item model picker advertising "1-21" while keys 10+ did nothing was a real, shipped bug, caught only on a PTY); a value passed in the `unnumbered` set (e.g. a trailing "← назад"/"quit" entry) gets `·` instead of a digit, so it never eats a shortcut a real item needs. An optional `hint` string renders below the list. Every printed row (heading, item, hint) is truncated to `shutil.get_terminal_size().columns` on a real TTY via `_fit` — **this is a correctness fix, not cosmetic**: a row longer than the terminal wraps into extra physical rows the in-place redraw's `frame_lines` counter (a count of logical rows) doesn't know about, and the menu visibly creeps down the screen on every keypress (this actually happened: the `add` wrapper-picker rows were 85-90 columns wide before this fix, wrapping on any 80-column terminal). Off a TTY nothing is truncated — there's no redraw to protect. The heading and hint each get one blank spacer line for visual separation from the list, folded into the SAME `print_fn` call as a leading/trailing `\n` (not a separate call) — so `frame_lines = len(pairs) + 2 + (2 if hint else 0)` (was `+1`/`+1` before spacers existed) is the one place that has to know about them; get it wrong and the redraw erases the wrong number of rows. Navigation: arrows or vim `j`/`k`, `Home`/`End`/`g`/`G`, `PageUp`/`PageDown`, digits `1`-`9` for direct selection. `MenuCancelled` carries `hard: bool` — `True` for Ctrl-C (immediate, unconditional exit), `False` for Esc/`q` (default "go back one level"); defaults to `True` so an un-inspected `except MenuCancelled` keeps the old "cancel = stop" behavior. **Ctrl-C in raw terminal mode never raises `KeyboardInterrupt`** (`ISIG` is off) — it arrives as the raw `\x03` byte and MUST be translated to its own `"HARD_CANCEL"` key, distinct from Esc/`q`'s `"CANCEL"`; folding them together silently turns every Ctrl-C into a soft "back" instead of "quit everything" (a real regression this project shipped and fixed — see `tests/test_keys.py::test_ctrl_c_is_a_distinct_hard_cancel`). `press_any_key(prompt)` is the public "block for one keypress" primitive (TTY-gated, no-op off a TTY) used by the TUI's post-command pause; it fully parses one key via the same layer, so an escape sequence isn't misread as several separate "any key" presses. The cursor is hidden for the duration of a menu (`\033[?25l`/`\033[?25h`), restored in a `finally` even on exception. On a real TTY the menu redraws *in place* each keypress (cursor-up + clear-to-end ANSI escapes), so navigation doesn't scroll an endless stack of menus; on a non-TTY (pipe/tests with injected `print_fn`) it falls back to reprinting each frame.
- **Reading a raw keypress: `os.read(fd, 1)`, not `stream.read(1)`.** `sys.stdin` is a buffered `TextIOWrapper` — a single `.read(1)` call is free to pull more than one byte off the fd into its own internal buffer before decoding and returning the first character. `select.select` only ever sees the fd itself, with no visibility into that internal buffer, so a byte the wrapper already buffered can never show up as "ready" again — `_read_more`'s `select` call then waits out its timeout for a byte that already arrived, and the *next* menu redraw's `read_key()` blocks forever on a `select` that will never fire. This was a real, hard-to-reproduce hang (only under a real PTY driving fast keypresses — the injected-`read_key` test suite can't see it at all) — `_read_key_raw` reads every byte straight off the fd via `os.read` instead, so `select` and the actual read never disagree about what's pending. Bytes are decoded **one at a time** with `errors="replace"`, so a multi-byte UTF-8 character (a Cyrillic letter, say) becomes several U+FFFD → `"OTHER"` keys — harmless for a menu that only acts on ASCII and ignores `"OTHER"`, but this reader is **not** reusable for text input without first accumulating continuation bytes into a whole character.
- **Peeking past a keypress needs pushback (`_pending_byte`).** `_translate` peeks one byte past Enter to detect the LF half of a CRLF. A peeked byte is already off the fd and cannot be un-read, so when it turns out *not* to be the pair byte — the user pressed Enter and then, within the window, another key — it must be parked in the module-level `_pending_byte` slot and drained by the *next* `_read_key_raw` call, which is why that slot is module-level rather than a local. Dropping it instead (the original "swallow whatever shows up" behavior) silently lost that keypress: "Enter then Down" typed quickly just didn't move. The peek uses `_PAIR_TIMEOUT` (~2 ms), not `_ESC_TIMEOUT` (50 ms) — a real CRLF pair arrives in one burst from the terminal driver, so the longer wait bought nothing and added 50 ms of latency to *every* Enter. One byte of pushback is enough: only the Enter branch pushes, at most one byte, and the next call drains it before it can read anything else. `_translate`'s `push_back` parameter defaults to a no-op discard so every caller that only wants key *names* (and every `_translate` unit test) is unaffected.
- **`cli/tui.py`** — a looping arrow-key menu wrapping the CLI 1-to-1 (issue #3's contract: CLI primary, TUI secondary, no new *behavior*). `run_tui` mutates the shared `argparse.Namespace` (`name`/`model`/`dry_run`/`debug`) and calls the *same* `_handle_list` / `_handle_add` / `_handle_edit_token` from `cli/parser.py` — it never touches `services/` directly, so TUI and CLI cannot diverge in behavior. The one read-only exception is `services/wrappers.py`'s `describe_all` (built on `is_installed`), called purely to label menu entries — `_handle_edit_token` in `parser.py` builds the exact same shape of labels over its own (secret-only) subset of `WRAPPERS`, so this one helper is what keeps the two wrapper-listing menus from drifting apart on either row layout or the `Paths`/`is_installed` wiring behind it. Labeling and screen order are presentation, not behavior, and are the TUI's job: every menu item shows a description, and `add`'s wrapper/settings sub-menus show install state / the current toggle value, none of which duplicates a service call or validation rule. Navigation is uniform: **Esc/`q`** goes back one level (a sub-menu returns to the main menu; the main menu exits) via `MenuCancelled.hard=False`, folded by the local `_pick` helper into the same `_BACK` sentinel value picking the visible "← назад" item returns — every call site checks the result ONE way; **Ctrl-C** (`hard=True`) is left to propagate as `MenuCancelled` and is caught once, at the very top of `run_tui`, so it exits the whole TUI immediately from any depth rather than being handled ad hoc at each call site. Every sub-menu also has a visible `← назад` entry, since the keyboard shortcuts aren't discoverable from the screen alone; it (and the main menu's `quit`) is passed to `select_from_menu`'s `unnumbered` set, and `_pick` derives the hint's digit range (`1-4`, not always `1-9`) from how many *other* items are on screen — see `_hint` — so the printed range can't drift from what the digits actually do. There is no `dry-run` menu toggle — `--dry-run` is a scripting/debugging flag, read from `args` but never mutated by the menu; `code-helper --dry-run` (or `tui`) still works. `debug` lives in a `settings` sub-menu instead of main-menu real estate. `add`'s model prompt is two menu picks (wrapper, then "keep default" vs "enter custom") rather than a bare `input()` — the common case never calls `input()` at all, and the default model is shown in the label. A separate `new` entry runs the constructor (agent → provider → model → alias); `add` is left untouched, because the two are different operations and merging them would make the menu ambiguous. `_run_add` clears the axis fields before dispatching: the loop reuses one `Namespace`, so a previous `new` run would otherwise leave `args.agent` set and flip a later preset install into constructor mode. The model picker shows at most `MAX_DIGIT_ITEMS` entries and discloses the remainder on the manual-entry row ("ещё N") — a 20-model list otherwise scrolled off the top of a normal terminal. A `CodeHelperError` from `add`/`edit-token` is printed to stderr and the menu reappears (re-raised under `--debug`, mirroring `__main__.main`); a `KeyboardInterrupt` from a plain `input()` (the custom-model prompt) is also caught and treated as "back", never crashes the TUI. After a command runs, the screen clears and the menu re-renders at the top — but only after a keypress (`[нажмите любую клавишу, чтобы вернуться в меню]`), so the command's output stays readable instead of being wiped instantly; on a non-TTY the pause is a no-op so tests never block; a hard Ctrl-C mid-command skips the pause entirely (the user already asked to leave). Both `select_from_menu` and `input` are looked up at call time (not bound as function defaults) so tests can `monkeypatch.setattr` them — a `= input` default parameter would bind the builtin at def-time and silently ignore the patch. `_handle_edit_token`'s own wrapper picker (in `parser.py`) re-raises a hard `MenuCancelled` instead of swallowing it into `"cancelled"` + exit 0, specifically so a TUI caller can still tell "back" from "leave the whole TUI" apart even though that handler is shared with the plain CLI path.
- **`services/model.py`** — the two axes and the rule connecting them. `Agent` (claude, codex) and `Provider` (ollama, zai) each declare a `frozenset[ConfigShape]`; **compatibility is their intersection**, not a hand-written pair table. `ConfigShape` is the hidden third axis — *how* an agent gets pointed at a backend: `ANTHROPIC_ENV` (env vars around `claude`), `OLLAMA_LAUNCH` (delegate to `ollama launch <agent>`), `OPENAI_TOML` (Codex's `[model_providers.X]` profile). The intersection is why the impossible combinations need no special-case code: `claude × <openai-only provider>` is `∅` and refuses itself, which matters because such endpoints genuinely 404 on `/v1/messages`. `resolve_shape` picks by a fixed priority (`ANTHROPIC_ENV > OPENAI_TOML > OLLAMA_LAUNCH` — direct HTTP beats needing another binary on `PATH`) and is pure/IO-free, so a menu may call it to filter what it offers. `_validate_registries()` runs at import and constrains `Agent.binary` to `[a-z][a-z0-9_-]*` — that is what makes it safe for `render.py` to interpolate it unquoted. Ollama appears with **all three** shapes: the daemon serves the Anthropic protocol directly (`ANTHROPIC_ENV` — the `deepseek` preset), `ollama launch` can configure an agent for us (`OLLAMA_LAUNCH` — the `glm-ollama` preset), and its OpenAI-compatible `/v1` endpoint feeds Codex's own TOML profile (`OPENAI_TOML` — `codex × ollama` by priority now, no launcher binary needed). The priority `ANTHROPIC_ENV > OPENAI_TOML > OLLAMA_LAUNCH` means `codex × ollama` resolves to the TOML profile, not the launcher — the launcher stays reachable via `--shape ollama-launch`.
- **`services/spec.py`** — `WrapperSpec` is the *output* of resolution, not the input: by the time one exists, compatibility is checked, the model resolved, the alias validated. `build_spec` (from the axes) and `spec_from_preset` (from a named `Preset`) share one construction path, so a preset cannot drift from the equivalent hand-specified combination. `TierModels` keeps per-tier models expressible — `glm` really does use `glm-4.7`/`glm-5-turbo`/`glm-5.2[1m]`, which a single `--model` cannot express and which is why presets remain a concept rather than dissolving into the axes. `suggest_alias` derives `<model>-<agent>` (`glm-5:cloud` + codex → `glm-5-codex`) and **refuses an empty derivation** rather than collapsing to the bare agent name, which would have targeted `~/.local/bin/claude` — a real, working symlink on a normal install.
- **`services/render.py`** — one renderer per `ConfigShape` in `_RENDERERS`, dispatched on the shape `resolve_shape` already chose, so "is this allowed" and "how is it written" cannot disagree. Keyed by shape rather than by `(agent, provider)` because the pair table grows multiplicatively while shapes stay a handful, and a new provider reusing an existing shape needs no renderer at all. Not a method on `Provider` either — that would turn the registry from data into behavior. `render_script` has **no** `model_override` parameter: the model is decided in `build_spec`, which is what lets each renderer be a straight-line function of its input. A renderer returns the bash **wrapper** body only; the `OPENAI_TOML` renderer (`_render_openai_toml` → `exec codex --profile <alias> "$@"`) is the one shape whose wrapper is not the whole story — the model/base_url/wire_api live in a sibling TOML profile and model catalog, written by two *pure* helpers alongside the renderer: `openai_toml_body(spec, catalog_path)` (the `~/.codex/<alias>.config.toml` profile — `base_url` derives `/v1/` from the provider's Anthropic-root `base_url`, never touching that field) and `openai_catalog_body(spec)` (a `model_catalog_json` so Codex learns the context window of models it does not ship knowledge of — `_DEFAULT_CONTEXT_WINDOW` is a floor, no axis carries the real value). TOML values go through `_toml_string` (the per-target escape equivalent of `_shell_single_quote`); `agent.binary` is the one bare interpolation, safe only because of the import-time regex above. An unimplemented-but-recognised shape still raises "not implemented yet" — deliberately a *different* error from "incompatible" — for a provider that declares `OPENAI_TOML` but has no renderer entry.
- **`services/naming.py`** — `validate_alias`, an **allow-list** (`[A-Za-z0-9][A-Za-z0-9._-]{0,63}`). The name becomes an executable on `PATH`, so enumerating dangerous characters is not viable. Rejects `.`/`..`, path separators, leading `-`, whitespace/control bytes, and `RESERVED_ALIASES` — the agent binaries plus `code-helper`, because a wrapper named after the binary it execs recurses forever once `~/.local/bin` precedes the real one on `PATH`.
- **`services/models_api.py`** — `list_models(provider)` over stdlib `urllib`, no subprocess. Two shapes selected by `provider.model_list_api`: Ollama `/api/tags` (`models[].name`) and the OpenAI standard `/models` (`data[].id`). Note the path is `/models`, not `/v1/models` — an OpenAI-compatible `base_url` already ends in `/v1`. **Never raises**: a missing daemon is not a failure of the user's request, just the loss of a picker, so failures come back as `ModelListResult.error` and the caller falls back to manual entry. The caught tuple must include `http.client.HTTPException` **explicitly** — it is *not* an `OSError` subclass, so a server closing mid-body (`IncompleteRead`, `BadStatusLine`, `RemoteDisconnected`) escaped and crashed both `--list-models` and the TUI's model picker, neither of which wraps the call precisely because of this documented contract. An empty list with no error is a legitimate answer; what to do about it is the UI's call. `fetch` is an injectable seam (the project's `getpass_fn`/`read_key`/`print_fn` pattern) so tests never touch the network.
- **`services/wrappers.py`** — the generated-script lifecycle only: `install_wrapper` / `is_installed` / `is_managed` / `discover_managed` / `list_wrappers` / `describe_*`. It re-exports the spec and render names so older imports keep working. `describe_wrapper` (one formatted `name / state / description` row) + `describe_all` (that row per spec, paired with its name, each state resolved through `is_installed`) are the single source of truth for every wrapper listing — `list_wrappers`, the TUI's `add` picker, and `edit-token`'s picker all render through `describe_all`, so none of them re-derives `script_for(...).exists()` inline; the helper shares the `Paths`/`is_installed` wiring, not just the column widths. Callers pass their own `installed_word`/`not_installed_word` (English for `list_wrappers`, Russian for the TUI) — only the format is shared. `install_wrapper` takes a resolved spec (or a preset name, for compatibility) and honours the ownership guard below. The shape selects a **file plan** — one entry for most shapes (`_wrapper_plan`), three for `OPENAI_TOML` (`_openai_toml_plan`: bash wrapper + `~/.codex/<alias>.config.toml` profile + `~/.codex/<alias>.model.json` catalog) — and one orchestrator (`_install_plan`) writes whichever plan it was handed, so the per-file lifecycle (idempotence, ownership guard, discard-only-secret, dry-run/atomic-write) lives once instead of being re-implemented per shape. Each plan entry is a `_FilePlan` (path, body, mode, `managed_check`, `is_wrapper`); `is_wrapper` is the explicit flag that says only the bash-wrapper slot can carry a secret, so only it participates in the discard-only-secret check. The install is **atomic w.r.t. the guard**: `_decide` resolves each file's fate once (reading and checking it once — the refusal and write passes share that one decision, so nothing is re-read), then in a non-dry-run install every foreign / discard refusal is raised BEFORE any file is written (a foreign TOML profile never leaves the wrapper half-installed). Each of the three files has its own ownership check — `_is_ours` (marker OR legacy byte-match) for the wrapper, `_is_ours_marker_only` for the TOML profile (carries the marker comment, no legacy form), and `_is_our_catalog` for the catalog (JSON has no comments, so authorship is structural: a `{"version":1,"models":[...]}` body); `_is_ours_marker_only` and `is_managed` are both thin wrappers over one `_marker_at(path)` sniff so the read order and the "unreadable = not ours" exception tuple live in one place. `discover_managed` finds ad-hoc wrappers by their marker, since no preset knows about them and there is no state file; the TOML/catalog siblings are silent to `list` (it scans `bin_dir` only) — the bash wrapper's marker is the ad-hoc wrapper's only public record.
- **`services/secrets.py`** — resolves a wrapper's token: env var first, hidden `getpass` prompt otherwise. No persistent config file — the token lives only inside the generated script. **Not used by `edit-token`**: that command always prompts via `getpass` directly, because `resolve_token`'s env-var-wins behavior would otherwise silently ignore whatever the user types when the env var (e.g. `ZAI_API_KEY`) happens to already be set. **`edit-token` resolves the INSTALLED script, not the preset** (`spec_from_installed`, falling back to `get_spec`): passing a preset *name* to `install_wrapper` re-expands the preset from scratch, which silently reverted a model the user had chosen with `--model` — a credential rotation is not licence to change an unrelated setting. Reading the script back also makes the command reach wrappers built from the axes, which have no preset to look up at all and were previously unreachable from both the named form and the picker. The marker line carries agent/provider/shape and the body carries the models, so the installed file is a complete record of its own axes — which is what makes this possible without a state file. **Read ALL THREE tiers, never just one**: recovering a single model and letting `build_spec` synthesize `TierModels.uniform` silently rewrites the two tiers it did not read, and `glm` — whose haiku/sonnet/opus genuinely differ, the entire reason presets survive — is exactly where that bites. The first attempt at this fix did precisely that, and its test passed because it only exercised a uniform `--model` override; a non-uniform case is now pinned. A **markerless** file has no recorded axes, so it is matched against a same-named preset with the models taken from the body — but only if re-rendering the result reproduces every non-token byte. That re-render is the proof of authorship: without it, any file merely *named* like a preset would be adopted and overwritten. **The marker's `shape=` must be passed back into `build_spec`, not re-derived**: `claude × ollama` is compatible with *both* shapes and `resolve_shape` prefers `ANTHROPIC_ENV`, so dropping it turned a wrapper installed as `ollama launch` into an `ANTHROPIC_*` env block — not a changed model but a changed *mechanism*. The sibling `_respec_from_body` already threaded the shape through, which is how the omission was spotted: two reconstructors of the same thing disagreed.
- **`services/paths.py`** — frozen `Paths` dataclass, two fields (`bin_dir = ~/.local/bin`, `codex_dir = ~/.codex`). `Paths.from_home(home)` is pure path arithmetic; `Paths.default()` wraps `Path.home()`. `script_for(name)` carries a **structural** guard (`Path(name).name != name`) rejecting anything that is not a single path component — `'../../etc/passwd'` used to resolve outside `bin_dir` and `''`/`'.'` to the directory itself. This duplicates part of `validate_alias` on purpose: that one owns the messages and runs early, this one guarantees no code path — including a future one that forgets to validate — can write an executable outside `bin_dir`. The `OPENAI_TOML` shape needs the same guarantee for its two `~/.codex` siblings, so `codex_config_for(alias)` (`~/.codex/<alias>.config.toml`) and `codex_catalog_for(alias)` (`~/.codex/<alias>.model.json`) run the *same* single-component check. The predicate itself lives once in `_require_single_component(name, noun=...)`, called by both `script_for` (`noun="wrapper name"`) and the codex accessors (via `_single_component(alias, suffix=...)`, `noun="alias"`) — each public accessor still enforces it independently (the structural-safety argument is preserved), only the condition text is shared, with a pluggable noun for the error message. `--alias` reaches those paths too, and a `../../` alias would otherwise drop a profile outside `~/.codex`. Both accessors refuse `''`/`'.'`/`'..'` and anything containing a path separator.
- **`backends/_atomic.py`** — the only code that touches the filesystem. `atomic_write(path, data, mode)`: temp-sibling + fsync + `os.replace`, crash-safe.
- **`errors.py`** — `CodeHelperError` lives here (not in `__main__`) to avoid a class-identity split under `python -m`.
- **`__main__.py`** — `main()` dispatches and owns the `CodeHelperError` → `error: …` contract; **`cli()` is the console-script entry** (`pyproject.toml` points at it) and wraps `main` with the interrupt contract. The split is load-bearing: `MenuCancelled` must keep escaping `main` — that is how `edit-token`'s picker lets a TUI caller tell "go back" from "leave the whole TUI", pinned by `test_edit_token_hard_cancel_propagates` — but at the *process* boundary there is no such caller, so letting it out printed a raw traceback instead of the one-line contract. Catching it inside `main` fixes the terminal and breaks the TUI; catching it one level above fixes both. Exit code 130, matching a real SIGINT.

## Key Constraints

- **Agents and providers are DATA** — adding either is a registry entry, never new logic. A wrapper is a resolved point in agent × provider × model, and a `Preset` is just a named bundle of those arguments expanded through the same `build_spec`.
- **Compatibility comes from the data, not a table.** Both sides declare their `ConfigShape` set and the intersection decides. Never add an `if agent == ... and provider == ...` branch: that is precisely what this design removes, and it is why a new provider cannot silently create a broken combination. Keep "impossible" (`resolve_shape`, empty intersection) and "not built yet" (`render_script`, no renderer for a recognised shape) as **separate errors** — collapsing them would hide the extension point.
- **One renderer per shape**, keyed by the shape `resolve_shape` returned. The `--` before `"$@"` in the launcher shape is required for **both** agents: without it the launcher's own flag parser eats forwarded agent flags (verified — a bare `-p` yields `unknown shorthand flag: 'p'`).
- **The `auth` mode** (`"literal"` / `"secret"` / `"none"`, carried by the provider) keeps this generic: a literal token (Ollama's daemon accepts `"ollama"`) needs no prompt and gets mode `0o755`; a secret is resolved interactively/from env and gets `0o700` (owner-only — the script holds it in plain text).
- **Shell-injection defense**: every value interpolated into a generated script — token, base URL, model names — goes through `_shell_single_quote` (POSIX `'` → `'"'"'`). This matters because `--model` and `--alias` make those values user-controlled input, not registry constants. The single exception is `agent.binary`, guarded structurally instead (import-time regex) so the generated line reads `ollama launch claude`, not `ollama launch 'claude'`.
- **Validate before prompting.** `build_spec` checks compatibility and the alias *before* any caller resolves a token, so a typo or an impossible pairing can never trigger an interactive secret prompt for a wrapper that will not be written. The old `get_spec`-first flow had this property; it is pinned by a test that patches `resolve_token` to explode.
- **Ownership marker (reversal of the earlier "no ownership guard").** Every generated script carries `# code-helper: managed wrapper …` on line 2; `is_managed` reads it back. The earlier position was not wrong, it was *conditional*: overwriting by name was safe while the set of names was closed and curated (three, chosen by the author). A user-chosen `--alias` removes that precondition and can name anything on `PATH`. So: our own wrapper is replaced silently, a **foreign** file needs `--force` or an interactive confirm, `--dry-run` never prompts, and `confirm=None` (no TTY) fails fast with the `--force` hint rather than blocking on stdin that will never arrive. There is still no "remove" command. **One narrow exception to "replaced silently": discarding the only copy of a token.** A `secret` wrapper carries its token nowhere but the script — no config file, and the provider's `*_API_KEY` is a possible *source*, not a guaranteed copy — so replacing one with a wrapper that never asked for a token loses it irrecoverably, and `--alias` makes that reachable by a typo. `_discards_only_secret` gates exactly that: outgoing `auth == "secret"` AND incoming `auth != "secret"`. It routes through the same `force`/`confirm`/`dry_run` machinery as the foreign-file guard, so there is no new CLI concept. Deliberately **not** "the body changed" — that would prompt on every model bump and token rotation (`add`-as-update, the primary use), and a prompt seen constantly is one users learn to dismiss, costing more safety than it buys. `secret → secret` stays silent on purpose: the old token goes away, but the user was just prompted for the new one, so it is a deliberate replacement, not a silent loss (dropping that half of the predicate makes `edit-token`'s own tests fail). **The marker postdates the tool, so ownership cannot be the marker alone**: every wrapper installed by a previous release lacks it, and keying purely on the marker classified the tool's own prior output as foreign — telling users a file "was not created by code-helper" about a file it *did* create, and leaving `edit-token` (which has no `--force`) with no way forward at all. `_is_ours` therefore accepts a second proof: a body byte-identical to what the pre-marker release would have written for that same spec (`render_legacy_script`, which drops the marker line from the current render rather than duplicating the bodies, so the two cannot drift). Deliberately an **exact** match, not a heuristic — one byte off is still foreign. The token is blanked before comparing, because `edit-token` is by definition called with a *different* token than the installed file embeds; matching on it would fail in exactly the case this path exists to unblock. **The pre-guard idempotence read must never raise**: it runs *before* the guard, so a `UnicodeDecodeError` there (a binary at the target path — newly reachable via `--alias`) aborted with a traceback instead of reaching the guard whose whole job is to handle that file, and `--force` could not rescue it. `_read_text_or_none` returns `None` — never `""`, which would compare equal to an empty render and slip through as "ours".
- **No Rich/Typer** — plain text, argparse (stdlib) only.
- **`--dry-run`** never writes any file — prints what would happen instead.
- **TUI is a mirror, not a second implementation**: every TUI menu item must dispatch into an existing `_handle_*` with the same arguments the CLI subcommand would build — no state-changing service calls, no duplicated validation (e.g. `edit-token`'s secret-wrapper filter lives once, in `_handle_edit_token`). "Mirror" means no new *behavior* — it does not forbid presentation: item descriptions, install-state labels, and screen order are the TUI's own responsibility. The permitted read-only exceptions are now three, all IO-free-or-harmless lookups used purely to decide what to put on screen: `describe_all` (labels), `compatible_providers` (don't offer a pairing that would only fail later), and `list_models` (the model picker; it never raises, so a dead daemon degrades to manual entry).
- **`--provider` selects the mode, never a guess.** `add <name>` is always a preset; `add --agent … --provider …` is always the constructor; both together is an error. The two namespaces don't overlap today, but a heuristic would silently change meaning the day they do. A bare agent name (`add codex`) gets a message showing the constructor form rather than a plain "unknown".
- **`OPENAI_TOML` is implemented but still the extension point.** It is declared *and* has a renderer now (`codex × ollama` → `_render_openai_toml` by priority, `~/.codex/<alias>.config.toml` + `~/.codex/<alias>.model.json` alongside the wrapper), so `codex × ollama` no longer reports "not implemented yet" — it writes a TOML profile and launches `codex --profile <alias>`, never touching `~/.codex/config.toml`. The shape *remains* the extension point for the *next* OpenAI-compatible provider: wiring one up is still just a `PROVIDERS` entry (declaring `OPENAI_TOML`) reusing the existing renderer — no change to the axes model, the CLI, or the TUI. A provider declaring `OPENAI_TOML` but with no renderer entry still resolves here and still surfaces as "not implemented yet" from `render_script` — distinct from "incompatible", a different, honest error. Codex cannot be configured by environment variables at all (there is no `OPENAI_BASE_URL`); it needs a `[model_providers.X]` profile with `base_url`/`wire_api`/`env_key`, which is why this is a distinct shape rather than a variant of the env one.

## Testing

- **Markers**: `@pytest.mark.unit` / `.integration`. `--strict-markers` in `addopts` turns a typo'd marker into a hard collection error.
- **HOME isolation**: `conftest.py`'s autouse `_isolate_home` fixture sets `HOME=tmp_path` for every test. `Paths.from_home(tmp_path)` is the test seam; production code only ever calls `Paths.default()`.
- Every install/render behavior is pinned in `tests/test_wrappers.py`, including shell-injection regression tests on every channel (token, `--model`, and the command shape). Also there: the ownership guard — a foreign file is refused, `--force` overrides, `confirm=None` fails fast, `--dry-run` never prompts, and replacing *our own* wrapper never asks (a test passes a `confirm` that raises if called). The `OPENAI_TOML` block adds the multi-file analogues: three files written, idempotence across all three, a foreign *TOML profile* refused (and `--force` overriding it), `--dry-run` listing all three with nothing written, and replacing our own never prompting — plus the renderer bodies (`openai_toml_body` carries marker/model/`base_url` with `/v1/`/`wire_api`; `openai_catalog_body` carries the context window), TOML-quoting of a model with `:` and `.`, the `--profile` quoting in the wrapper, and `Paths.codex_config_for`/`codex_catalog_for` rejecting a non-single-component alias.
- **`tests/test_model.py`** — the axes and compatibility. The load-bearing one is `test_openai_only_provider_is_incompatible_with_claude`: it uses a provider that is deliberately **not** in the registry, so nothing in `model.py` could be hard-coded to know about it, yet the refusal still comes out right — that is the proof compatibility is computed rather than enumerated. `test_codex_with_openai_only_provider_resolves_to_toml` guards the extension point from the *other* direction: it uses an out-of-registry OpenAI-only provider that resolves to `OPENAI_TOML` (valid) but has no renderer, and asserts `resolve_shape` does **not** refuse — "impossible" and "not built yet" stay separate errors even now that `OPENAI_TOML` has a renderer for `codex × ollama`. `test_codex_ollama_uses_toml` / `test_codex_ollama_launcher_shape_is_reachable` pin the priority choice (TOML by default, launcher via `--shape ollama-launch`), and `test_ollama_declares_three_shapes` keeps the provider's shape set honest.
- **`tests/test_naming.py`** — the alias allow-list, plus `Paths.script_for` tested *independently* of `validate_alias` so the structural guard is proven on its own.
- **`tests/test_models_api.py`** — every failure mode asserts "no exception, populated `error`", since call sites are allowed to ignore the outcome. All with an injected fetcher; no network.
- **`tests/test_cli_add.py`** — both `add` modes through `main([...])`, the disambiguation rule, and that an invalid combination never reaches a token prompt (patches `resolve_token` to explode). The constructor-mode test asserts the `codex --profile <alias>` wrapper plus the TOML profile and catalog siblings; a separate test pins the `--shape ollama-launch` fallback (launcher writes ONLY the wrapper, no siblings); `test_two_agents_on_one_model_coexist` forces `--shape ollama-launch` so its assertion stays about coexistence, not which shape priority picked; and `test_list_matrix_shows_a_gap_for_incompatible_pairs` checks `codex × ollama = openai-toml` in the matrix.
- **`tests/test_keys.py`** — unit tests of `cli/menu.py`'s pure `_translate` key-sequence parser, with a fake `read_more` (no TTY needed). Pins the escape-sequence edge cases that used to be entirely untested (`_read_key_raw` was never exercised end to end — every menu test injects `read_key` and bypasses the parser): a lone Esc must resolve via a non-blocking peek, not block forever; CSI (`\x1b[A`) and SS3 (`\x1bOA`, application cursor mode) both map arrows; a multi-byte sequence like F5 (`\x1b[15~`) is fully consumed, not partially — leftover bytes previously "pressed" spurious menu items; CRLF/LFCR swallows *only its actual pair byte* (on the short `_PAIR_TIMEOUT`, not the 50 ms `_ESC_TIMEOUT`) so Enter neither double-fires nor eats a fast follow-up keypress, and a non-pair byte is pushed back rather than dropped; `\x03` (Ctrl-C) is a *distinct* `"HARD_CANCEL"`, never folded into `q`/Esc's `"CANCEL"`. One test (`test_read_key_raw_pushback_survives_into_the_next_call`) drives the real `_read_key_raw` over an `os.pipe()` with `termios`/`tty` stubbed — the only test that covers the module-level pending-byte slot, which `_translate` alone cannot prove.
- **`tests/test_menu.py`** — unit tests of `select_from_menu`/`press_any_key` with an injected `read_key` (and a `_FakeTTY` stdout stand-in for the ANSI-redraw assertions). Covers `(value, label)` pair rendering, `hint` correctly extending the redraw frame's line count (a silent-drift-prone number — see `frame_lines` in the source), digit/Home/End/PageUp/PageDown navigation, `MenuCancelled.hard` for both the `"HARD_CANCEL"` key and an injected `KeyboardInterrupt`, cursor hide/show (including on an exception path), truncation to a monkeypatched `shutil.get_terminal_size` (and its absence off a TTY), and numbering (`unnumbered` items get `·` not a digit, and `DIGIT_3` still resolves to the correct item when an unnumbered entry sits before it in the list).
- **`tests/test_tui.py`** — the TUI path is exercised through `main(["tui"])` / `main([])`, patching `code_helper.cli.menu.select_from_menu` and `builtins.input` (both looked up at call time inside `cli/tui.py`, so the patch reaches them). Menu choices are returned **by value**, not by rendered label. Because the menu loops, every command test's menu sequence ends in `"quit"` (the loop would otherwise re-prompt once the fake is exhausted); `add` sequences list two picks (wrapper, then `"__default__"` or `"__custom__"`) since the model prompt is no longer a bare `input()`. One test (`test_tui_add_installs_same_as_cli`) installs via TUI and via CLI into two separate `HOME`s and asserts the generated script bodies are byte-identical — the actual proof of the 1-to-1 contract; `test_tui_new_matches_the_cli_byte_for_byte` extends that to the `OPENAI_TOML` constructor path, comparing all three files between two `HOME`s (the wrapper and catalog are byte-identical; the TOML profile embeds an absolute `model_catalog_json` path, so it is compared modulo that home path); `test_tui_loops_after_command` runs two commands before `quit` to prove the loop; `test_tui_error_returns_to_menu` patches `resolve_token` to raise and asserts the error is printed and the menu reappears rather than exiting; `test_tui_soft_cancel_in_submenu_returns_to_main_menu` / `test_tui_hard_cancel_exits_from_submenu_depth` pin the Esc-vs-Ctrl-C navigation contract at sub-menu depth; `test_tui_hard_cancel_inside_edit_token_picker_exits_tui` proves a hard cancel from the CLI-shared `_handle_edit_token` code path still reaches the TUI's top-level catch instead of being swallowed into "cancelled, pause, redraw".
- Manual verification of ANSI redraw/hang behavior on a REAL TTY (these tests all inject `read_key`/`select_from_menu` and cannot see terminal-driver-level bugs — the Ctrl-C/`stream.read` issues above were only caught this way): a `pexpect`-driven PTY session works well for this, since it sets up terminal attributes a hand-rolled `pty.fork()` harness easily gets wrong (a source of false-positive hangs during this project's own debugging). **Always wait for the frame's last line before sending a key**: `pexpect` can otherwise write before the child finishes `tty.setraw`, and the byte is eaten by the cooked-mode line discipline. Sending early gives ~50% spurious "hangs" on identical runs; waiting gives 6/6. The `new` flow's two display bugs (the `1-21` hint and the 20-row model list) were both found this way and are invisible to the suite.
